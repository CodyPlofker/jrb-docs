RFC: Packshot-Composite Architecture

Drafted 2026-05-07 morning at the end of the overnight engine-patches session.

Author: Claude (Cody to review fresh before approving).

Status: PROPOSAL — not implemented yet.

TL;DR

Stop asking GPT-image-2 to render the product. Generate the scene only (no product), then composite a clean packshot from the refset on top at exact pixel coordinates. Result: 100% of cells have pixel-perfect subject size, position, CTA clearance, and headline contrast — the AI variability only affects the aesthetic of the background, not the layout integrity.

Why this is the unlock

The overnight engine-patch sprint hit a hard ceiling at 19/24 cells (v4). Six engine patches landed real wins (orphan-word avoidance, width-fit shrink, auto-contrast hardening, packaging-spec strengthening, wordmark-orientation rule). But the remaining 5 failures are all rooted in one limitation:

GPT-image-2 unreliably honors size + position constraints when generating "stick on a surface in a scene." It complies maybe 60% of the time on 9×16. When it doesn't, prompt-strengthening + auto-iterate can't reliably fix it without introducing new failure modes.

Specifically, the auto-iterate experiment (v5/v6) showed:

  • Vision-based size detection over-triggers AND under-triggers (false negatives like c1 1×1 v5).
  • When regen produces a smaller subject, it can land directly in the CTA reserve zone, creating CTA-on-stick collisions (c5/c9/c12 9×16 in v5/v6).
  • A "don't make it worse" guard helps at the margin but doesn't cross the next ship-rate threshold.

The architecture is the bottleneck, not the patches.

Proposed architecture


                         BEFORE (current)
                         ───────────────
  Brief → buildPrompt → openaiGenerate → composite (text overlay) → blob

                         AFTER (proposed)
                         ───────────────
  Brief → buildPrompt (scene-only, "no product")
       → openaiGenerate → bg.png
       → composite:
           1. paste bg
           2. paste packshot.png at exact (x, y, w, h) per format spec
           3. drop shadow under packshot (sharp blur + alpha)
           4. headline + subhead + CTA on top
       → blob

The product layer is deterministic:

  • Subject vertical anchor: ALWAYS y=820 (1×1) / y=1500 (9×16). Pixel-perfect.
  • Subject height: ALWAYS 32% of canvas height. Pixel-perfect.
  • Subject horizontal anchor: ALWAYS centered.
  • CTA clearance: ALWAYS ≥60px. Mathematically guaranteed.
  • Wordmark orientation: ALWAYS upright (packshot is canonical).

The AI is now responsible only for the LAYER UNDER THE PRODUCT — the surface, the lighting, the props, the mood. Things models are reliably good at.

What changes in the codebase

  1. New: lib/packshots.ts — small registry of clean packshots per product/shade. PNG with transparent background. Mini MB (closed jar top-down + 3/4 angle), Foundation Stick (cap-on standing + cap-off standing), etc. Source: existing Air refset images, alpha-cut via the remove.bg API or hand-prepped.
  1. Modified: lib/prompts.ts — when a concept is in packshot-composite mode, drop the SUBJECT SIZE block and the packaging-fidelity block from the prompt. Replace with: "Render this scene WITHOUT the product. Generate the surface, lighting, and any contextual props EXCEPT the JRB product itself. Leave a clean, well-lit empty area in the lower-middle of the frame where a product will be placed in post."
  1. Modified: lib/composite.ts — new compositePackshot() function:

```typescript

const packshot = await loadPackshot(concept.packshotId, concept.shade);

const targetH = canvas.height * 0.32;

const targetW = packshot.height ? packshot.width * (targetH / packshot.height) : packshot.width;

const x = (canvas.width - targetW) / 2;

const y = format === '9x16' ? 1500 - targetH/2 : 820 - targetH/2;

const shadow = await sharp(packshot).blur(20).modulate({ brightness: 0.3 }).resize(...).toBuffer();

overlay.composite([

{ input: shadow, top: y + 20, left: x + 4 },

{ input: packshot, top: y, left: x }

]);

```

  1. New: per-concept opt-in flag. Add concept.compositionMode: "ai-rendered" | "packshot-composite" so existing concepts keep working and we test the new path on a small set first. Default = "ai-rendered" (current behavior). Toolkit briefs that want pixel-perfect output set "packshot-composite" explicitly.

What we'd lose

  1. Realistic shadow + surface contact. A composited packshot has a fake drop shadow, not light bouncing onto a marble counter. We can fake it well (Y-blur shadow with directional softness based on the AI scene's lighting direction), but discerning eyes will notice on big tests.
  1. Scenes that REQUIRE product interaction. Hand-holding-product (c10 UGC), product-on-rumpled-sheets, product-in-spill, product-being-used. The AI needs to render the product when a hand or surface deformation interacts with it. → For these archetypes, fall back to ai-rendered mode.
  1. Per-shade automatic packshots. Mini MB has 16+ shades. We'd need a packshot per shade (or a base packshot + a tinted swatch overlay, which is doable with sharp).

What we'd gain

  1. 100% pixel-perfect subject layout. Size, position, CTA clearance — guaranteed.
  2. Wordmark orientation always correct (packshots are canonical).
  3. Logo hierarchy always correct (packshot has the right label).
  4. Shade fidelity is exact (instead of model averaging "across multiple shade refs").
  5. Faster iteration — text/CTA changes don't require regen.
  6. Auto-iterate becomes ~unnecessary — most failures are layout, layout is deterministic.
  7. Vision-based detection becomes optional (use it for QA, not retry triggering).

Effort estimate

  • Day 1: build lib/packshots.ts + alpha-cut a Mini MB packshot + a Foundation Stick packshot + a basic shadow-rendering helper in lib/composite.ts. Wire compositionMode flag into the Concept type and generate.ts. Smoke test on 1 concept.
  • Day 2: run a 12-cell toolkit in packshot-composite mode. Compare against the v4 baseline (also 12 cells, ai-rendered). Iterate on shadow realism. Confirm Mini MB regression still passes.
  • Day 3: per-shade packshot tinting helper. Document the workflow. Update SKILL.md.

Risk areas

  1. Shadow realism. The compositor needs to read the AI scene's lighting direction (luminance gradient sample) and cast a shadow that matches. Rough first pass: hardcode "upper-left light → lower-right shadow." Iterate from there.
  2. Surface integration. If the AI scene has a clear horizon line (a marble counter behind a linen surface), we need to anchor the product on the right surface. First pass: prompt the AI for a SINGLE-SURFACE scene (no horizon line, no surface change in the lower band). Iterate as needed.
  3. Per-concept tuning. Some archetypes (Open purse spill, Lifestyle in-use) rely on product-in-context. These would either stay ai-rendered or get a hybrid pipeline (AI generates the scene with a placeholder element, we mask + replace).
