01 · Architecture at a glance

Two surfaces, one pipeline.

Surface 1 — The Skill

/static-ads lives in ~/.claude/skills/static-ads/SKILL.md. It's a 480-line Claude Code skill — basically a giant playbook the model reads at runtime.

It interviews me, pulls customer intelligence, checks past angles, drafts scene direction, delegates copywriting to a separate skill (/jrb-copywriter), assembles a JSON brief, fires it at the engine, polls until done, then builds a comparison HTML page.

Surface 2 — The Engine

jrb-static-ads is a Next.js 16 app at ~/Desktop/01-Projects/jrb-static-ads.

Web UI for browsing briefs + a Studio for hand-building one. API routes for /api/briefs, /api/refsets, /api/review-bank, plus a per-cell iterate endpoint. Under the hood it talks to OpenAI gpt-image-2 and Gemini Nano Banana Pro, stores state in Upstash Redis, and saves outputs to Vercel Blob.

Stack

  • Next.js 16 · React 19 · TypeScript · Tailwind 4
  • Image generation: OpenAI gpt-image-2 (primary), Gemini nano-banana-pro (co-equal, ~37% cheaper)
  • Scene writing: Claude Haiku 4.5 — auto-fills a 150–200 word scene description when I leave it blank
  • State: Upstash Redis (briefs, assets, status)
  • Storage: Vercel Blob (final composited PNGs)
  • Compositor: sharp + server-side font rendering (Canela Light + ArticulatCF Bold + BaseMonoWide)
  • References: Air MCP for real JRB photography; never AI-generated humans
02 · End-to-end flow

From "I want ads" to a 48-cell grid.

01

I describe what I want in plain English

"I want a Mini Miracle Balm toolkit aimed at Suburban Super-Mom focused on trial-risk." That's it. The skill picks up from there.

02

Research pre-load (before any question)

The skill auto-pulls our customer intelligence repo, reads the angle registry to make sure we're not repeating what we already shipped, and queries existing refsets in the engine. It surfaces 4–6 lines of context before asking anything.

03

The 8-question intake

Sequential — one question at a time. Mode, product, persona, angle, creative direction, awareness stage, toolkit size, reference ads, exclusions. If I batch-answer, it accepts and skips ahead.

04

Copy is delegated to /jrb-copywriter

This is a hard rule. Claude never writes JRB headlines, subheads, or CTAs from inside /static-ads. It briefs a separate skill that owns voice + style + claims compliance, then surfaces the options to me.

05

Scene direction

For each concept the skill drafts 2–3 distinct scene alternatives (composition, surface, light, props), I pick one, and it expands into a fully prescriptive scene paragraph using a "Scene Anatomy" template — explicit zones, lighting direction, surface material, prop positions, "top 55% empty" callouts.

06

Brief JSON → POST /api/briefs

The skill assembles a JSON brief (product, angle, personas, refsetId, concepts[]) and POSTs to the engine. Engine returns a briefId immediately and starts generating fire-and-forget.

07

The engine fans out — N concepts × 2 formats × M models

For each cell the engine: loads real product references (Air photos), injects per-product training rules, builds a final prompt with brand guardrails, calls the image model, downloads the output, composites brand fonts on top via sharp, uploads to blob, marks ready.

08

Skill polls until ready, builds a comparison page

Polls every 15s. Toolkit (48 cells) takes 8–12 min, first-principles (4–8 cells) takes 1–3 min. Then it generates a comparison HTML page with a diversity audit panel, downloads every PNG, grades each one visually against a 4-point checklist, and writes the verdict inline.

09

I review, iterate, ship

Greens go to Meta. Yellows get fed back to /static-ads with a one-sentence delta and the engine re-renders just that cell at a versioned URL. Reds get killed.

03 · The skill

/static-ads — the brain.

A 480-line markdown file the Claude Code agent reads at runtime. No code execution of its own — it's pure instruction, plus tool calls (file reads, curl, Air MCP).

What lives in it

  • Three modes (First-principles, Toolkit, Iteration) and when to pick which
  • Universal hard rules that apply to every output
  • A research pre-load checklist (customer intelligence, angle registry, refsets)
  • The 8-question intake
  • A toolkit recipe — 6 archetypes × 2 hook types = 12 entity-distinct slots
  • A claim-distinctness audit (NLP-style "would Andromeda read these as different?")
  • An 8-axis embedding-distance audit (every pair must differ on ≥4 axes)
  • Scene Anatomy template + 3 reusable scene templates proven 4/4 in production
  • 13 known failure modes with their iterate deltas
  • A "done-gating" checklist before I'm allowed to call something shipped

The whole skill is grounded in Meta research

Andromeda + GEM (Meta's ad-ranking embedding models) reward diversity in the creative pool. We don't run one ad and scale spend — we ship 12 truly different ads per persona/angle and let the auction find the winner. The 8-axis audit (composition, palette, lighting, claim type, etc.) is the heuristic for "truly different" that maps onto how Andromeda actually clusters embeddings.

04 · Three modes

Pick one before anything else.

Mode A — First-principles

One or two sharp concepts. Best-of-best on a single angle. New territory exploration.

1–2 concepts · 2 models · 2 formats · 4–8 cells · ~$1.20

Mode B — Toolkit

Twelve truly-different ads that earn distinct Meta entity IDs by varying ≥4 of the embedding-distance axes per pair, while sharing one persona + one core angle. This is the default for broad-testing into Andromeda.

12 concepts · 2 formats · 1–2 models · 24–48 cells · $7.20–$14.40

Mode C — Iteration

A specific cell underperformed and needs a delta fix. Skill hands off to /ad-iteration-brief which diagnoses against Northbeam/Polar metrics, then we fire the engine's per-cell iterate endpoint.

1 cell · ~$0.30

06 · Universal hard rules

Things the system will refuse to break.

These run on every output regardless of mode. Most exist because we hit the failure mode in production and locked in the rule afterwards.

Copy & voice

  • Copy comes from /jrb-copywriter, never the model. Every headline, subhead, and CTA is delegated. Writing copy inside /static-ads is a hard process violation.
  • Only the 6 canonical JRB personas. Ageless Matriarch (60+), High-Powered Executive, Wellness Practitioner, Suburban Super-Mom, Creative Entrepreneur, Dedicated Educator. Never invent a persona.
  • No invented quotes. Customer-voice claims, founder-voice notes, review snippets in image — all verbatim from real sources only.
  • No unapproved clinical claims. All percentages, "100% of users", "improves", "barrier", "hydration" must come from the approved claims sheet, verbatim.
  • Bobbi Brown attribution. Any time Bobbi's named, "Founder" or "Makeup Artist" must follow — otherwise the copy implies the other Bobbi Brown brand (which she sold).
  • Verify claims before shipping. Wear time, clinical stats, shade counts — must match LP/PDP language exactly.

Imagery

  • No AI-generated humans. Faces, hands, bodies all come from Air refs. AI is fine for backgrounds, textures, packshots, surfaces, UGC context.
  • No invented branding on non-JR objects. Every dropper bottle, book, glasses, cup must be unbranded. Each scene paragraph calls this out explicitly.
  • No press logos. No Vogue / Allure / Cut / "AS SEEN IN" bands. We don't have rights.
  • Image-headline match. The scene must telegraph "this is a foundation ad" within 1 second.

Composition (the hard pixel rules)

  • No copy ever overlaps the product. Headline, subhead, and CTA each clear the product bounding box completely.
  • Subject occupies 26–42% of frame height (not 60–80%), vertically centered around y=820 (1×1) or y=1500 (9×16).
  • Top 55–60% reserved for headline + subhead. Bottom 5–10% reserved for CTA pill.
  • ≥80px clearance between subhead bottom and product top. ≥60px clearance between product bottom and CTA pill top.
  • No orphan-word wraps. Never break "for", "of", "and", "the", "or", "a" onto its own line.
  • JONES ROAD wordmark on the lid only. Never wrapped around the jar body.
  • Wordmark orientation: when a product lies horizontal, the wordmark still reads upright to the viewer — never rotated 90° sideways.

Output

  • Output sizes: 1080×1080 (1:1) and 1080×1920 (9:16). Meta safe zones enforced by the compositor.
  • Brand fonts composited server-side — Canela Light (headline), ArticulatCF Bold (subhead, ALL CAPS, ls .3px), BaseMonoWide (CTA). The image model never renders text.

08 · What's actually driving the output

The prompt is assembled, not handwritten.

Every image-model call gets a multi-block prompt that's stitched together from ~15 different sources. Here's what goes in, in order.

The assembler — buildPrompt()

One function. Pulls everything into one structured string. This is the signature:

// lib/prompts.ts:328
export function buildPrompt({
  concept,                  // archetype, scene, persona, headline, subhead, cta
  format,                   // "1x1" | "9x16"
  product,                  // "Mini Miracle Balm"
  angle,                    // one-sentence creative angle
  mode,                     // "branded" | "ugc" | "advertorial"
  hasRealPersonReference,
  allowGeneratedPeople,
  hasReferences,
  hasMoodReference,
  moodReferenceCaption,
  referenceAdCaptions,
  reviewNuggets,            // verbatim customer quotes selected in Studio
  antiReferenceCaptions,    // "don't look like this" — competitor anti-refs
  brandDirectionBlock,      // JRB-wide brand context
  productDirectionBlock,    // per-product training (FIRST in the stack)
  safeZonesBlock,           // pixel-precise safe-zone rules
  shadeLabel,
  shadeRefCount,
}: PromptInputs): string

Brand guardrails — same on every call

The JRB_GUARDRAILS constant is the brand-wide preamble. Lives in lib/prompts.ts. Excerpt:

PACKAGING FIDELITY IS THE #1 RULE — read this before anything else.
Jones Road Beauty product packaging is sacred. The product's exact form,
material, label copy, branded ink color, proportions, and WORDMARK
PLACEMENT must match the real product. Never reinvent, stylize, simplify,
or approximate packaging.

Composition rules (apply to every scene):
- HARD PIXEL RULE — TOP CLEARANCE. The TOP edge of every subject element
  (jar, lid, hand, balm interior, propped object, leaning lid, swatch
  streak — every visible non-background element) MUST sit at or below:
    • 1:1 (1080×1080): pixel y=540
    • 9:16 (1080×1920): pixel y=960
  The upper half is RESERVED for a headline + subhead composite.
- FULL-BLEED PHOTOGRAPHY — the photographic content must fill the ENTIRE
  output frame edge to edge with NO INTERNAL WHITE BORDER.
- BALM INTERIOR DEFAULTS TO USED — for any open-jar shot, the visible
  balm surface MUST look used: show a finger-swipe scoop, a gentle swirl,
  or surface relief from real scoop behavior. NEVER render a flat,
  glassy, mirror-smooth, untouched, freshly-poured balm surface — that
  reads as drugstore / e-commerce stock photography.
- WORDMARK ORIENTATION — when a product is shown lying horizontally,
  the JONES ROAD wordmark MUST remain readable from the viewer's
  perspective. NEVER render the wordmark rotated 90° from the viewer.

Per-product training — the FIRST block

Each product has its own training MD at data/products/<slug>/training.md. This goes in as the very first block of the prompt, before brand guardrails — because the model pays the most attention to the top. Excerpt from Mini Miracle Balm:

⛔️ HARD ANTI-RULES — these are the failures we keep seeing.
   NEVER do any of them.

SIDE-WALL TEXT — the jar's body is plain unprinted opaque white
plastic. Period.

DO NOT print, stamp, emboss, or render ANY of the following on the
jar wall:
- "MINI MIRACLE BALM"
- "BAUME MIRACLE MINI" (French translation — JRB does not use French)
- "8.5g", "0.3 oz" — any net-weight stamp
- "JONES ROAD" anywhere on the side wall (LID TOP only)
- Bilingual or trilingual side labels
- Ingredient lists, made-in tags, batch codes

WORDMARK PLACEMENT — "JONES ROAD" on the LID TOP, nowhere else.

JAR PROPORTIONS — SHALLOW puck, NOT a tall jar.
Mini Miracle Balm is a shallow disc, total height ≈ 2 cm.
Lid thickness ≈ jar body height (lid:body ratio ~1:1). The whole
jar is wider than it is tall.

JAR MATERIAL — opaque white plastic, never glass or transparent.
The balm color inside is visible ONLY from the OPEN top when the
lid is off — never through the side walls.

BALM SHADE — match the attached reference EXACTLY. NEVER invent
a color. NEVER average two reference shades into a new fictional
color.

These rules are the scar tissue of every failure mode we've shipped a fix for. The model used to invent French labels and net-weight stamps to "look professional." Now it doesn't.

Format-specific composition — the format note

Different format = different geometry. The formatNote is constructed per-format with pixel-exact bounds. 9×16 excerpt:

Vertical 9:16 (1080×1920).

🔴 SUBJECT SIZE — THIS IS THE #1 COMPOSITION RULE.
   THE SUBJECT MUST BE SMALL RELATIVE TO THE FRAME.

- Subject TOTAL HEIGHT: between 26% and 40% of canvas height
  (between 500px and 770px tall).
- Subject TOTAL WIDTH: never exceeds 50% of canvas width (max 540px).
- NEVER render the subject as a close-up that fills most of the frame.
- NEVER render the subject larger than 45% of the canvas height.
- The subject is a small editorial product hero, not a macro close-up.
  Think 'Vogue editorial pull-quote treatment' not 'Sephora product
  detail page.'

POSITION: Subject's vertical CENTER at y=1500 (range y=1450–1550).
Subject TOP edge between y=1200 and y=1300.
Subject BOTTOM edge between y=1700 and y=1820 — NO part of subject
may extend below y=1820.

CLEARANCE ZONES (HARD PIXEL RULES):
- Upper 60% of canvas (pixel y=0 to y=1150) MUST be empty surface —
  no jar, no lid, no balm, no shadow extending up. This is the
  headline + subhead composite zone.
- Bottom 5% (pixel y=1820 to y=1920) MUST be empty for the CTA pill.

CRITICAL: NO part of the JONES ROAD wordmark, lid printing, or any
branded surface may appear in pixel y=0 to y=1300 — at least 200px
of clear empty surface BETWEEN the bottom of the typography zone
(~y=1100) and the top of the lid wordmark.

Scene writer — when I leave the scene blank

If a concept's scene field is empty, the engine invokes Claude Haiku 4.5 to write one, seeded by the archetype + angle + any reference notes + selected review nuggets. Lives in lib/scene.ts:

// lib/scene.ts — abridged
const JRB_SCENE_RULES = `JRB brand rules:
- No AI-generated faces (unless archetype is UGC or problem-solution)
- Clean, elevated, editorial aesthetic
- Natural light preferred (golden hour, window light, overcast)
- Products are the hero — no clutter
- Neutral backgrounds: white, cream, linen, sand, warm gray
- Real skin, real texture — never retouched or perfect
- For "Hero product": product alone, beautiful still life, macro detail
- For "UGC-style": hand holding or using product, casual but polished
- For "Editorial / press": minimalist, product + whitespace, type-forward
- For "Lifestyle in-use": product integrated naturally into a moment
- For "Problem-Solution": before/after texture or skin close-up`;

export async function generateScene(input: SceneInput): Promise {
  // Brief composed of: product, archetype, angle, reference notes,
  // scene nudge, selected review nuggets — anthropic Haiku writes
  // a 150–200 word visual scene description.
  const message = await client.messages.create({
    model: "claude-haiku-4-5-20251001",
    max_tokens: 300,
    messages: [{ role: "user", content: prompt }],
  });
  return message.content[0].text.trim();
}

The final prompt order

  1. Per-product training (Mini MB, FS, etc.) — FIRST
  2. JRB brand-wide guardrails
  3. Format-specific composition note (1×1 vs 9×16)
  4. Archetype direction
  5. The scene paragraph (either hand-written or Haiku-generated)
  6. Product reference notes (real Air photos attached separately)
  7. Reference ads (past winners / competitor inspiration) — interpret style, don't copy products
  8. Mood reference (if attached)
  9. Anti-references (Merit / Saie / Glossier / Rare) — "don't look like this"
  10. Review proof points (verbatim customer quotes from Studio picker)
  11. Shade lock (if a specific shade is requested)
  12. Safe zones
  13. Negative prompts

10 · Refsets & references

Real photography, locked.

A refset is a saved pack of cropped, rect-parameterized Air imgix URLs that lock product identity. We never let the model hallucinate the jar. Every concept attaches a refset → real packshots get sent as input images to the model alongside the prompt.

What else gets auto-attached at runtime

  • Anti-references — Merit, Saie, Glossier, Rare ads, attached as a separate "don't look like this" block.

11 · Code-composited treatments

When the model isn't allowed to render text.

Some ad formats are too text-heavy or too brand-strict for the image model to handle. For those, the engine renders the entire ad in code (TypeScript + sharp, or Python + PIL) — the model is either bypassed entirely or only generates the ambient lifestyle background.

When we promote a one-off proven winner into the registry, it becomes a permanent template — Mini MB winners cascade into Foundation Stick, Lip Recharge, etc., without rebuilding the visual system from scratch.

12 · Iteration loop

Per-cell fixes, versioned.

When a cell scores yellow on the 4-point checklist, I write a one-sentence delta and the engine re-renders just that cell at a new versioned URL. The comparison page updates to point at the new version. Original is preserved.
